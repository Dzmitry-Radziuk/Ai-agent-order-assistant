# Передача контекста проекта

## Текущее состояние

По анализу `vmui_logs_export.jsonl` исправлены ошибки разбора входных сообщений в
общих владельцах правил, без изменения системных промптов и инфраструктуры.

Исправлены:

- проверенная локальная привязка комментария больше не теряется, если ИИ вернул
  неполный `source_line`; правило работает для одной позиции и списка;
- фрагмент, который входит в название товара после нормализации регистра,
  пунктуации, `ё/е` и безопасных окончаний, не дублируется комментарием
  поставщику;
- граница семантического списка: склонения товара больше не приводят к потере
  подтверждённых позиций;
- словесные количества и формы единицы «мешок» восстанавливаются из исходной
  фразы, при этом не создаётся неуказанное количество;
- разговорные и ошибочно распознанные вводные слова не попадают в
  `product_query`;
- приветствия и свободная беседа отделены от истории поставок;
- близкий кандидат каталога сохраняется для выбора, если противоречие добавлено
  моделью, а не подтверждено требованиями пользователя;
- добавлены регрессионные проверки для списков, количества, приветствий,
  разговорных вводных и кандидатов.

## Исправлено в текущей итерации

- Если ИИ уже вернул корректное название, словесное количество вида «пару/пара
  <единица>» из исходной фразы больше не возвращается в `product_query` при
  сверке. Очистка выполняется единым правилом только при совпадении единицы с
  исходной фразой; оно не затрагивает названия вроде «пара обуви».
- При сетевом таймауте OpenAI для одной однозначной позиции применяется только
  подтверждённый детерминированный разбор. Списки, комментарии, диапазоны и
  принудительный AI-режим по-прежнему требуют ответа модели и не угадываются.
- Границы позиций учитывают словесное количество перед товаром, поэтому
  количества в фразах вроде «один килограмм ... и два килограмма ...» не
  перераспределяются между товарами.
- Для опечаток добавляются отдельные похожие кандидаты с причиной `similar`;
  они не выбираются автоматически и не удаляются из списка после ответа модели
  `not_found`. Числовые характеристики и ограничение поставщика проверяются.
- Если ИИ вернул `unknown`, указательная фраза без самостоятельного названия
  товара не восстанавливается детерминированно в новую позицию. Это устраняет
  расхождение, когда пользователю показывали «не распознано», а метрика всё же
  записывала успешное `add_items`.
- Новый названный товар без количества теперь безопасно прерывает открытую
  карточку `not_found`, сохраняет старую проблемную строку и проходит обычную
  сверку каталога. Ранее такой ввод ошибочно считался ответом на старую карточку.
- Если ИИ пропустил локальное требование, начинающееся с явного маркера
  («обязательно», «желательно», «только» и т. п.), оно восстанавливается только
  из `source_span` своей позиции и сохраняется комментарием. Привязки ИИ и
  глобальные комментарии этим резервным путём не изменяются.
- Роль весового диапазона подтверждается исходной фразой, а не уверенным
  значением модели: без явной просьбы о фасовке диапазон остаётся каталожным
  признаком, а отдельное «нужно 10 кг» — количеством заказа.
- Разговорные формы «картошка/картошки/картошку» дают только похожие варианты
  каталожного «картофеля». Они не считаются точным совпадением и не выбираются
  автоматически.
- Словесное «пару <единиц>» определяется по локальному фрагменту конкретной
  позиции до или после маркера. Поэтому «пару килограмм лука», «лука пару
  килограмм» и голосовой список сохраняют количество у своего товара; единица
  соседней позиции не переносится через разделитель.
- Локальная привязка «пару <единиц>» также учитывает запятую перед комментарием:
  «филе форели, пару килограмм, обязательно зачищенное» больше не теряет
  подтверждённое количество.
- Границы источника устойчивы к склеенным кириллическим строкам без пробела
  (`ФранцияГорчица`); такой хвост не попадает в соседний `product_query`.
- Числовая цена (`202₽`, `202`) не принимается за `supplier_hint`, если в исходной
  фразе нет явной связи с поставщиком.
- При тайм-ауте текстового AI однозначная одиночная позиция со словесным
  количеством может безопасно пройти детерминированный fallback; списки,
  комментарии и неоднозначные фразы по-прежнему не угадываются.
- Целевые проверки количества, границ источника, комментариев и каталога прошли;
  полный набор из 100% тестов прошёл с `PYTHONPATH=.`; `mypy src` также завершён
  без ошибок. Первый запуск полного pytest без `PYTHONPATH=.` дал только ошибки
  импорта пакета `scripts`, поэтому он не считается проверкой кода.

## Следующий шаг

Выполнить ручной сценарий в Telegram на чистом черновике (`/reset`): голосом
«картошки 8 килограмм, только без червей» и выбрать один из вариантов.

«томаты 5 кг, только красные; огурцы 4 кг, только без червей» — каждое
пожелание должно остаться только у своей позиции. Для «свиная шея без костей
5 кг» признак остаётся в названии и не дублируется комментарием. Также проверить
`яблак 15 кг`, «Картофель старый» при открытой карточке ненайденного товара и
фразу «Все эти лежитки оранжевые». Quick Tunnel
работает только пока запущен процесс `cloudflared`; при его смене нужно обновить
`PUBLIC_BASE_URL`, пересоздать сервисы и повторно выполнить `set-webhook`.
