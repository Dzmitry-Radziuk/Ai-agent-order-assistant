# Тесты Python-бота

Тесты сгруппированы по бизнес-областям, а не по внутренним модулям реализации:

- `ai/` — структурированные ответы OpenAI, голос и фотографии;
- `api/` — health endpoints и приём Telegram webhook;
- `catalog/` — поиск, ранжирование и безопасный выбор товара;
- `config/` — загрузка и проверка настроек окружения;
- `conversation/` — состояние диалога, комментарии и карточки интерфейса;
- `docs/` — целостность пользовательского каталога и его связей с pytest;
- `input/` — команды, парсер и голосовые маршруты;
- `product_add/` — запросы снабжению на добавление товара;
- `quantity/` — количества, единицы, кратность и дубликаты;
- `repositories/` — транзакционные контракты хранения сессий, заявок и привязок;
- `submission/` — история, Google Sheets и надёжная отправка заявки;
- `supplier/` — выбор поставщика и минимальная сумма заказа;
- `telegram/` — команды, callback и транспорт Telegram;
- `venue/` — регистрация заведения и изоляция каталогов;
- `workers/` — фоновые задачи Celery и защита от повторного выполнения.

Полный локальный прогон:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\ruff.exe check src tests alembic
.\.venv\Scripts\mypy.exe src
```

Тесты не запускают n8n и не обращаются к боевым сервисам Telegram, OpenAI или Google Sheets. Экспорт n8n остаётся справочным источником поведения при переносе новых сценариев.

Пользовательский взгляд на критические маршруты находится в
[docs/USER_SCENARIOS.md](../docs/USER_SCENARIOS.md). Каждая критическая карточка
содержит ссылку хотя бы на один существующий pytest-тест.
